# AI Startup Validator — Backend API (Phase 6A)

## Overview

A minimal FastAPI backend exposing a single endpoint that runs the full
startup validation pipeline (ML inference + idea scoring) and returns a
structured JSON report.

---

## Requirements

Install API dependencies (in addition to the existing project dependencies):

```bash
pip install -r requirements-api.txt
```

---

## Running the API

From the **project root** directory:

```bash
uvicorn api.app:app --reload --port 8000
```

The server will start at `http://localhost:8000`.

Interactive docs (auto-generated by FastAPI):
- Swagger UI: `http://localhost:8000/docs`
- ReDoc:       `http://localhost:8000/redoc`

---

## Endpoint

### `POST /api/validate`

Validates a startup idea and returns a structured report.

**Request body (JSON):**

| Field     | Type   | Required | Description |
|-----------|--------|:--------:|-------------|
| `idea`    | string | ✅       | Startup idea description. Must not be empty. |
| `country` | string | ✅       | Country name or ISO-3 code (e.g. `"India"`, `"USA"`). |

**Example request:**

```bash
curl -X POST http://localhost:8000/api/validate \
     -H "Content-Type: application/json" \
     -d '{
           "idea": "An AI-powered platform helping restaurants reduce food waste.",
           "country": "India"
         }'
```

**Response shape (200 OK):**

```json
{
  "submission": {
    "idea_text": "...",
    "country_input": "India",
    "resolved_country": "IND",
    "resolved_categories": ["Analytics", "Clean Technology"],
    "is_complete_submission": true,
    "word_count": 9
  },
  "ml_result": {
    "predicted_class": 0,
    "pattern_label": "Failure Pattern",
    "ml_success_score": 0.4473,
    "ml_failure_score": 0.5527,
    "note": "This is a model-estimated success score based on historical structural patterns. It is NOT a probability or guarantee of real-world startup success.",
    "active_country_features": ["country_IND"],
    "active_category_features": ["cat_Analytics", "cat_Clean_Technology"]
  },
  "idea_evaluation": {
    "idea_evaluation_score": 32,
    "max_score": 100,
    "grade": "Developing",
    "note": "This score measures description clarity only. It does not predict business success.",
    "dimensions": [ ... ]
  },
  "narrative": {
    "strengths": [ ... ],
    "missing_or_unclear": [ ... ],
    "guidance": [ ... ]
  },
  "limitations": [ ... ],
  "scores_are_separate": true,
  "combined_score": null
}
```

**Important:** `ml_result.ml_success_score` and
`idea_evaluation.idea_evaluation_score` are kept as **separate** fields.
`combined_score` is always `null`. The two scores must not be combined
without an explicit documented design decision.

**Error responses:**

| Status | Condition |
|--------|-----------|
| 400    | Empty or whitespace-only `idea` or `country` |
| 422    | Required field (`idea` or `country`) missing from body |
| 503    | ML model unavailable (file missing or corrupt) |
| 500    | Unexpected internal error (no stack trace exposed) |

## Architecture

```
POST /api/validate
        │
        ▼
   api/app.py              ← FastAPI routing, request/response models
        │
        ├── inference/feature_extractor.py   ← Phase 4A: feature extraction
        ├── 05_evaluate_idea.py              ← Phase 4A+4B: ML + scoring
        └── inference/report_generator.py   ← Phase 5: report assembly
```

The backend **imports and reuses** all existing pipeline code. No ML or
scoring logic is duplicated.

---

## Constraints

- The trained Random Forest (`models/best_model.joblib`) is **not modified**.
- The 65 model features are **not changed**.
- Phase 4A feature extraction is **not modified**.
- Phase 4B scoring weights are **not modified**.
- No external APIs (Gemini, OpenAI, etc.) are used.
